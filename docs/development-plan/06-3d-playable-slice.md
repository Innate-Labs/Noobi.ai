# 阶段 06：第三人称 3D 基础与可玩样板

状态：开发中（已有部分专项/样板，不代表整阶段已完成或已验收）。实际进度以 [STATUS.md](STATUS.md) 为准。

## 目标与入口条件

通过选定方案自主生成一个能完整操作的代表性 3D 关卡。

- 前置条件：阶段 05 已由用户验收通过；对应记录可在 STATUS.md 查到。
- 需求追踪：R09 R07，见 [REQUIREMENTS.md](REQUIREMENTS.md)。
- 开发前必读：[README.md](README.md)、[STANDARDS.md](STANDARDS.md)。
- 代码入口（需开工时核实）：workspaceTemplate.ts、production/gameQualitySpec.ts、runtime/、godotToolBroker.ts、gameplayExperienceEvaluator.ts。拟新增服务名称不构成既有实现。

## 开发任务

- [x] 06-D01：组件化角色控制、相机避障、移动/跳跃、地形碰撞、交互与暂停。
- [x] 06-D02：加入一个敌人、轻战斗/负反馈、一个机关、一项能力和明确终点；固定更新与动画状态约定。

已勾选表示对应平台实现及工程自验已完成，完整生成作品和人工验收仍按下方 A/U 项及交付报告单独核对。

## 本阶段开发标准

- 先使用合格基础素材，阶段 07 补完整生成资产链；本阶段不冒充美术成品。
- 区分开发者写通用组件与 Noobi 自主生成项目；最终样板不得靠人工补游戏代码后宣称自主成功。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 06-A01 | 控制相机 | 跑坡、跳跃、靠墙、转角、焦点切换与鼠标锁定有真实输入证据。 |
| 06-A02 | 真实规则 | 战斗命中与空挥不同，机关满足条件才触发，失败与重开有效；禁止直接调用胜利函数。 |
| 06-A03 | 最小完整流程 | 从正常新游戏到达终点；保存退出再继续，关键状态保持正确。 |
| 06-A04 | 生成链路 | 记录需求→方案→自动制作→可玩关卡；至少两次独立生成，任何人工干预单独列出。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 06-U01 | 选择样板方案并等待生成 | 得到实际 3D 游戏，能直接进入。 |
| 06-U02 | 走动、转镜头、战斗、解机关并到终点 | 规则可理解，镜头和碰撞不阻止完成。 |
| 06-U03 | 受伤/失败，重开；保存退出再继续 | 状态按约定恢复，核心流程仍可走通。 |
