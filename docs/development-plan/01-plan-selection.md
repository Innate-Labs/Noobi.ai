# 阶段 01：制作方案生成、选择与开始

状态：待用户验收。实际进度以 [STATUS.md](STATUS.md) 为准。

## 目标与入口条件

文字需求先生成可比较方案，用户明确选择后才开始游戏制作。

- 前置条件：阶段 00 已由用户验收通过；对应记录可在 STATUS.md 查到。
- 需求追踪：R02 R03，见 [REQUIREMENTS.md](REQUIREMENTS.md)。
- 开发前必读：[README.md](README.md)、[STANDARDS.md](STANDARDS.md)。
- 代码入口（需开工时核实）：HomeDashboard.tsx、contracts.ts、main.ts、gameHarness.ts；拟新增 PlanStore/PlanService。拟新增服务名称不构成既有实现。

## 开发任务

- [x] 01-D01：定义 PlanDraft、PlanVersion、需求 ID、平台、范围、预算和关键假设；结构化输出在宿主验证。
- [x] 01-D02：新项目提供 2–3 套实质不同且满足共同必需要求的方案；小改动允许只有一套。
- [x] 01-D03：完成方案卡、详情、选择、错误/重试/取消状态；估算显示区间及依据，未测得的不编造数字。
- [x] 01-D04：开始按钮绑定选定方案版本，原子保存并创建制作运行；重复点击只能产生一次运行。

## 本阶段开发标准

- 此阶段复用已有制作管线，不宣称完整 3D 生成已实现。
- 未选择并开始前，允许已告知的方案模型调用，不启动游戏实现或素材生成；计入分析消耗。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 01-A01 | 入口门控 | 无选定方案时宿主拒绝开始；不能绕过 Renderer 直接调用旧 IPC。 |
| 01-A02 | 输入有效性 | 空响应、损坏 JSON、超时与不支持请求均有可恢复状态，不展示伪造方案。 |
| 01-A03 | 版本与并发 | 重复点击、重试、编辑保存与开始同时发生时，仅运行用户看到的正确版本。 |
| 01-A04 | 真实链路 | 至少 3 个固定需求通过真实规划模型生成方案；所选版本确实进入已有 Harness，保存运行证据。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 01-U01 | 输入包含明确 3D 要求的需求 | 看到 2–3 套方案，全部保留 3D，区别具体。 |
| 01-U02 | 查看方案详情后选择一套 | 范围、平台、假设清晰，未选择前没有游戏制作。 |
| 01-U03 | 点击开始，再快速重复点击 | 只出现一个制作任务，任务显示正确方案。 |

## 范围边界与风险

- 本阶段不做：暂不实现自由编辑、参考解析或新的 3D 模板。
- 风险处理：模型不能返回满足硬约束的方案时明确失败并支持重新生成，不降级隐藏要求。

## 退出条件与汇报

所有开发任务与适用验收项有证据，开发者自验通过后状态改为“待用户验收”，立即向用户汇报本阶段做了什么、怎么试、验证结果和遗留问题。只有用户明确验收通过，才改为“已验收”并进入下一阶段。存在未完成项时留在本阶段；范围变更必须先由用户明确接受。

用户未回复、等待超时、测试全绿均不等于用户验收通过。禁止提前填写完成日期或用户意见。
