# 阶段 12：完整游戏 UI 与真实状态绑定

新增来源：2026-09-26 用户要求继续完成原 Markdown 后，补齐生成游戏的 UI。长流程与生成样板在运行时，先完成可独立开发/验证的 UI 组件；这不代表前置阶段验收通过。

## 开发标准与任务

- [x] 12-D01：提供标题/继续、HUD、任务、背包/能力、区域地图、暂停/设置、失败重试、结局/返回标题组件。
- [x] 12-D02：显示和按钮绑定真实游戏状态；存档错误可见，成功保存后才反馈成功；菜单阻止世界与输入继续推进。
- [x] 12-D03：可按已选风格调整主题色、标题背景与字体；中文字体离线且许可可分发，键盘焦点、滚动和较小窗口可用。
- [x] 12-D04：真实音量总线、静音、图形缩放与设置跨进程恢复；进度存档和设置分开。
- [ ] 12-D05：在 Noobi 自主生成的完整成品中验证上述全流程及参考风格，而不只在工程夹具中运行。

## 验收标准

| 编号 | 检查 | 通过要求 |
|---|---|---|
| 12-A01 | 菜单闭环 | 鼠标/键盘实际从标题到游玩、暂停、保存/刷新/继续、失败/重试、结局，不能直接调用游戏胜利函数 |
| 12-A02 | 状态一致 | HUD数值、任务、物品、能力由权威游戏状态驱动；重复奖励和读档不一致不可通过 |
| 12-A03 | 交互隔离 | 菜单时物理与攻击停止；点击 UI 不穿透触发游戏行为；退出菜单镜头正确恢复 |
| 12-A04 | 设置与异常 | 无存档、坏存档、写入失败有正确结果；音量/静音与设置重启真实生效 |
| 12-A05 | 画面 | 1280×720、800×600实际截图无不可操作内容，中文无缺字；最终作品与 ArtBible 一致 |

工程夹具通过不等于成品通过；可配置主题也不等于每款游戏都已完成美术。

## 用户验收

在生成作品中点新游戏/继续，打开背包、任务和地图；暂停后按移动，确认角色不动；保存退出后继续，核对物品和任务；调整音量并重开，检查恢复。最后完成失败重试和结局返回标题。
