# Noobi 分阶段开发与验收入口

这套文件将已确认的产品规划转为可执行阶段。总体规划见 [完整规划](../NOOBI_3D_PRODUCT_DEVELOPMENT_PLAN.md)。建立日期：2026-09-25。

## 如何开始

1. 阅读本文件、[通用开发标准](STANDARDS.md) 和 [状态表](STATUS.md)。
2. 找到最早一个尚未验收的阶段，阅读该阶段 Markdown；仅当前阶段可以进入实现。
3. 开工前记录当前代码基线、范围、预算与可用环境；列出预期交付。
4. 完成实现、自动验证和真实运行验证，按 [汇报模板](REPORT-TEMPLATE.md) 写报告。
5. 向用户汇报，提供可运行版本和具体操作步骤，状态改为“待用户验收”。
6. 用户明确通过后记录结论；继续下一阶段。若有反馈，修复本阶段并重新交付。

阶段 00 已由用户验收；阶段 01 自验完成，当前待用户验收；阶段 02–11 尚未开始。查看 [阶段 01 交付报告](reports/01-delivery.md)。

## 两套流程必须区分

- 我们开发 Noobi：按本目录逐阶段实施，每阶段完成后交给用户验收，通过后进入下一阶段。这是用户本次明确提出的开发节奏。
- Noobi 为终端用户制作游戏：先提供方案，用户选择或修改并点击开始；随后内部自动推进制作、测试和修复，仅重大范围/预算变化需再次决策。不得把研发阶段审批硬塞进产品内部每一步。

## 边界与工作记录

本目录是执行顺序与验收的入口；总体规划解释产品背景。冲突时先遵守用户最新明确要求，再更新文档，不能自行放宽验收。

需求覆盖见 [REQUIREMENTS.md](REQUIREMENTS.md)。阶段状态只在 [STATUS.md](STATUS.md) 维护；报告写在 `reports/` 下，证据引用实际日志或工件，避免复制用户原始私有资料。

阶段文档完成不等于功能完成。生成成功、测试通过、开发者自验和用户验收分别记录。未来继续任务时可直接要求“按 docs/development-plan/README.md 执行当前阶段”。
