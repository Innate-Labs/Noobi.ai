# 阶段 04：短视频玩法理解与方案生成

状态：未开始。实际进度以 [STATUS.md](STATUS.md) 为准。

## 目标与入口条件

从片段生成带时间证据的玩法和风格规格，并融合用户改编要求。

- 前置条件：阶段 03 已由用户验收通过；对应记录可在 STATUS.md 查到。
- 需求追踪：R06 R07，见 [REQUIREMENTS.md](REQUIREMENTS.md)。
- 开发前必读：[README.md](README.md)、[STANDARDS.md](STANDARDS.md)。
- 代码入口（需开工时核实）：参考服务、方案服务；拟新增 VideoPreprocessor/ReferenceAnalyzer。拟新增服务名称不构成既有实现。

## 开发任务

- [ ] 04-D01：首期支持 MP4/MOV，用户选择关注片段，建议范围 30–120 秒；明确体积、分辨率和解码限额。
- [ ] 04-D02：保留时间戳进行镜头分段、关键帧提取和动作附近密集采样；音频若启用需保持同步。
- [ ] 04-D03：输出事件时间轴、可见状态变化、规则假设、未知项、剪辑/回放/过场标记。
- [ ] 04-D04：支持多来源按维度组合；用户文字及明确编辑优先于模型推断，分析结果进入方案。

## 本阶段开发标准

- 此阶段验收视频理解与计划，不把尚未生成的完整游戏写成已还原。
- 不能从移动画面断言具体按键，不能从一次血条变化断言精确伤害公式。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 04-A01 | 解码与恢复 | 不支持编码、超限、损坏、中断和取消不遗留运行任务；缓存避免重复分析。 |
| 04-A02 | 证据准确性 | 至少 6 个已知规则片段，覆盖实际游玩、剪辑、遮挡、快动作；关键结论有正确时间来源。 |
| 04-A03 | 规则辨别 | 必测规则断言逐项区分事实/推断；没有证据的关键规则不得作为已确认事实。 |
| 04-A04 | 需求融合 | “保留翻滚和体力，改成探索”进入选定规格；冲突参考有明确用途与解决方式。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 04-U01 | 上传一个片段并选择关注时段 | 可预览片段和时间轴，结论可定位回原画面。 |
| 04-U02 | 指出一次误判并添加玩法要求 | 理解卡及方案一起更新，已确认要求保留。 |
| 04-U03 | 上传含剪辑或 UI 遮挡的片段 | 系统说明观察局限，仍可编辑后继续规划。 |

## 交付物

视频入口、预处理、带时间证据的规格、测试片段标注与方案样例。

- 使用 [REPORT-TEMPLATE.md](REPORT-TEMPLATE.md) 建立 `reports/04-delivery.md`。
- 提供本阶段提交、运行/构建版本、日志与截图或录像链接、已知问题。
- 用户反馈后，将实际结论写入报告并更新 STATUS.md。

## 范围边界与风险

- 本阶段不做：不宣称恢复原游戏源码、隐藏规则或未展示关卡；不新增长视频全量分析。
- 风险处理：外部视频模型和处理成本必须记录；识别精度不足时限制支持范围并保留失败样本。

## 退出条件与汇报

所有开发任务与适用验收项有证据，开发者自验通过后状态改为“待用户验收”，立即向用户汇报本阶段做了什么、怎么试、验证结果和遗留问题。只有用户明确验收通过，才改为“已验收”并进入下一阶段。存在未完成项时留在本阶段；范围变更必须先由用户明确接受。

用户未回复、等待超时、测试全绿均不等于用户验收通过。禁止提前填写完成日期或用户意见。
