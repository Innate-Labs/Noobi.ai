## 开发任务

- [x] 03-D01：新增独立视觉参考记录与用途标记，首期 1–5 张 PNG/JPEG/WebP；与直接生产素材分开。

## 本阶段开发标准

- 截图不能证明操作、成长或隐藏规则；未知信息显式标记并结合用户描述补齐。
- 实际图片加载失败不得当作成功视觉分析；保留已传入图片的请求级证据。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 03-A01 | 入库边界 | 损坏图像、类型伪装、越界路径及总量超限受控失败；合法参考不进入生产素材证明。 |
| 03-A02 | 视觉输入 | 协议请求确实包含图像项；当前截图与正确构建 ID/哈希关联。 |
| 03-A03 | 真实理解 | 至少 5 组自有或授权参考覆盖不同镜头/风格；人工标注事实逐项核对，错误推断可编辑。 |
| 03-A04 | 视觉失败样例 | 当前构建黑屏/严重遮挡与正常样例对照，确认图像实际被评审读取；不凭路径字符串判通过。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 03-U01 | 上传两张图，分别指定美术和界面参考 | 用途独立，理解卡标出来源与未知项。 |
| 03-U02 | 把一项错误理解改正后生成方案 | 所有方案采用修改后的要求。 |
| 03-U03 | 查看参考与生成预览的关联 | 能看清使用的是哪张参考、哪个构建；本阶段不承诺成品 3D 相似度。 |

## 范围边界与风险

- 本阶段不做：不从单图承诺恢复完整三维几何或全部玩法；暂不处理视频。
- 风险处理：模型不支持图像时明确能力不足并提供可选兼容模型，不默默退回纯文字。
