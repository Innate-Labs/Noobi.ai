## 本阶段开发标准

- 默认复用合格基础素材，按需求生成特色素材；每件资产保存来源和必要授权信息。
- 生成代码或供应商宣称的面数和动画不是宿主验收结果；实际统计并验证播放与运行绑定。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 07-A01 | 真实建模链 | 至少一条真实参考图→Three.js→GLB→动画或已验证动画适配→场景使用闭环；记录版本、耗时和已知成本，未知明确标注。 |
| 07-A02 | 恢复与边界 | 保留已完成资产和失败原因；重启后明确继续或重试，失败、损坏文件、超预算和不支持角色结构有正确处理。 |
| 07-A03 | 资产合格 | 尺度、朝向、碰撞、挂点、贴图、预算、动画逐项验证，损坏资产不得标 ready。 |
| 07-A04 | 生产引用 | 运行中的角色确实使用目标模型与动作；账本存在但未使用必须判失败。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 07-U01 | 选择参考风格并生成核心资产 | 预览与实际场景均可查看，来源与状态清晰。 |
| 07-U02 | 移动和攻击，观察角色与武器 | 动画播放、脚底接地、武器挂点和碰撞符合样板需求。 |
| 07-U03 | 查看超预算或不支持资产的反馈 | 能理解问题和修复方案，失败不会被假装成功。 |
