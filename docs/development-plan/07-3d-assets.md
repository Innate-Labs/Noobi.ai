# 阶段 07：统一风格与游戏可用 3D 资产

状态：未开始。实际进度以 [STATUS.md](STATUS.md) 为准。

## 目标与入口条件

参考驱动的生成资产能够稳定绑定到实际游戏并通过运行验收。

- 前置条件：阶段 06 已由用户验收通过；对应记录可在 STATUS.md 查到。
- 需求追踪：R10 R05 R06，见 [REQUIREMENTS.md](REQUIREMENTS.md)。
- 开发前必读：[README.md](README.md)、[STANDARDS.md](STANDARDS.md)。
- 代码入口（需开工时核实）：mediaToolBroker.ts、mediaGenerationService.ts、mediaProviderStore.ts、assetStore.ts、assetPlanStore.ts；拟新增资产整理服务。拟新增服务名称不构成既有实现。

## 开发任务

- [ ] 07-D01：ArtBible 与 AssetSpec：风格、尺度、轴向、枢轴、碰撞、挂点、材质、动画和平台预算。
- [ ] 07-D02：整理可复用且有使用权的基础素材，接通一家原生图生 3D/异步任务供应商。
- [ ] 07-D03：实现远端任务 ID、查询/取消、去重、下载、校验、重试和计费记录；重启后可继续任务。
- [ ] 07-D04：加入必要的模型整理、转台检查、动画适配与引擎装配；主角/敌人/关键物件出现在真实场景。

## 本阶段开发标准

- 默认复用合格基础素材，按需求生成特色素材；每件资产保存来源和必要授权信息。
- 供应商宣称的面数和动画不是宿主验收结果；实际统计并验证播放与运行绑定。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 07-A01 | 真实供应商 | 至少一条真实参考图→模型→动画或已验证动画适配→场景使用闭环；记录模型版本、耗时、成本。 |
| 07-A02 | 恢复与边界 | 中断后恢复同一任务；失败、过期链接、超预算和不支持角色结构有正确处理。 |
| 07-A03 | 资产合格 | 尺度、朝向、碰撞、挂点、贴图、预算、动画逐项验证，损坏资产不得标 ready。 |
| 07-A04 | 生产引用 | 运行中的角色确实使用目标模型与动作；账本存在但未使用必须判失败。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 07-U01 | 选择参考风格并生成核心资产 | 预览与实际场景均可查看，来源与状态清晰。 |
| 07-U02 | 移动和攻击，观察角色与武器 | 动画播放、脚底接地、武器挂点和碰撞符合样板需求。 |
| 07-U03 | 查看超预算或不支持资产的反馈 | 能理解问题和修复方案，失败不会被假装成功。 |

## 交付物

一家供应商完整适配、基础素材库清单、生成资产样例、成本及运行验收记录。

- 使用 [REPORT-TEMPLATE.md](REPORT-TEMPLATE.md) 建立 `reports/07-delivery.md`。
- 提供本阶段提交、运行/构建版本、日志与截图或录像链接、已知问题。
- 用户反馈后，将实际结论写入报告并更新 STATUS.md。

## 范围边界与风险

- 本阶段不做：不同时接入所有供应商，不承诺动物/异形均可自动绑骨。
- 风险处理：阶段执行前写清供应商、账户和允许消耗上限；不能因已授权开发而推断无限付费生成。

## 退出条件与汇报

所有开发任务与适用验收项有证据，开发者自验通过后状态改为“待用户验收”，立即向用户汇报本阶段做了什么、怎么试、验证结果和遗留问题。只有用户明确验收通过，才改为“已验收”并进入下一阶段。存在未完成项时留在本阶段；范围变更必须先由用户明确接受。

用户未回复、等待超时、测试全绿均不等于用户验收通过。禁止提前填写完成日期或用户意见。
