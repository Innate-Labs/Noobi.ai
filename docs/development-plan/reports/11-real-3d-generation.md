## 预先确定的验收标准

- G01：从实际产品入口提交文字和图片，保留方案、选择及附件导入证据；记录规划阶段是否真正读取图片。
- G02：在 Noobi 内完成代码和素材生成；不以手写完整游戏替代产品能力。图片 → Three.js → GLB → Godot 的关键资产来源可追溯。
- G03：角色、地形、建筑、植被、机关、HUD 均有设计；主体不能以单个方块、胶囊或球体作为最终外观。运行清单完整，不能仅以资产数量判通过。
- G04：真实输入完成移动、碰撞、收集、机关、通关和重开；截图和报告对应同一当前构建，至少两处有效视角。
- G05：运行独立在线 Reviewer，记录其实际画面结论；自动技术检查不替代人工美术验收。
- G06：发现通用问题时修改平台并增加必要回归；修复后通过 Noobi 重试，保留失败原因与各阶段耗时，禁止削弱检查以宣称通过。
- G07：交付可打开的样板、截图、测试及修复记录，并明确未完成项。待用户确认画面与体验后才记为验收完成。

## 画面对照重点

| 主体 | 从参考图可见的设计 | 实机验收重点 |
|---|---|---|
| 章鱼 | 紫色圆头、卷曲触手、奶油色吸盘、大眼睛，托住整座岛 | 侧视仍有完整体积；触手有弯曲轮廓，不能退化为直圆柱 |
| 骑士 | 矮胖头盔、面甲槽、羽饰、条纹长枪、盾牌 | 主要识别部件齐全、比例统一，移动时身体和装备不脱离 |
| 青蛙商店 | 青蛙店主、木屋与柜台、招牌、瓶罐和道具 | 建筑及店主分别可辨认，交互点可接近，商店不只是纹理盒子 |
| 巨花 | 粉红花瓣、花心、绿叶与卷曲茎 | 花朵及叶片有厚度，激活反馈可见，不使用竖直图片冒充模型 |
| 岛与木桥 | 分层草地、紫褐土壁、两台一桥、栏柱与绳索 | 可走区域和碰撞一致，旋转相机后仍可理解通路 |
| 水池与鸭子 | 青色水面、数只圆润鸭子，位置低于主岛 | 有空间层次，鸭子造型与比例一致，避免穿插与遮挡 |
| 整体 | 明亮粉彩、深紫轮廓、圆润玩具体块 | 同时看全景与游戏视角；保留布局，HUD 清楚且不遮挡主要主体 |

背面与被遮挡部分是建模推断；不得声称单张图提供了完整三维真值。玩法由本次需求补充，未从图片推断成既有规则。
