## 预先确定的验收标准

- G01：从实际产品入口提交文字和图片，保留方案、选择及附件导入证据；记录规划阶段是否真正读取图片。
- G02：在 Noobi 内完成代码和素材生成；不以手写完整游戏替代产品能力。图片 → Three.js → GLB → Godot 的关键资产来源可追溯。
- G03：角色、地形、建筑、植被、机关、HUD 均有设计；主体不能以单个方块、胶囊或球体作为最终外观。运行清单完整，不能仅以资产数量判通过。
- G04：真实输入完成移动、碰撞、收集、机关、通关和重开；截图和报告对应同一当前构建，至少两处有效视角。
- G05：运行独立在线 Reviewer，记录其实际画面结论；自动技术检查不替代人工美术验收。
- G06：发现通用问题时修改平台并增加必要回归；修复后通过 Noobi 重试，保留失败原因与各阶段耗时，禁止削弱检查以宣称通过。
- G07：交付可打开的样板、截图、测试及修复记录，并明确未完成项。待用户确认画面与体验后才记为验收完成。

## 本轮发现的平台问题与修复

1. 场景报告写入使用相对路径，被安全写入器按宿主当前目录解析，导致真实试玩后误报“宿主产物路径逃逸项目目录”。已改为以工程根目录构造绝对目标，保持路径、符号链接和构建身份校验；增加三个回归。
2. 模型零件占用 350 个通用采样名额，使截图中实际存在的 HUD 漏采。通用遥测优先保留可见 UI 和角色物理状态；3D 几何继续走独立清单。上限不扩大，关键节点仍超限时明确报错。
3. 3D 角色通用遥测缺少可见性、视口标记，且位移阈值沿用 2D 像素量级。已按实际相机补充标记，3D 位移按世界单位处理；截图变化仍是必要证据，位置数据不能单独判玩法通过。

真实 Godot 回归：400 个网格与 400 个普通装饰节点之后的 HUD/角色仍被保留；几何清单完整；400 个关键控件超限时明确失败。命令 `NOOBI_GODOT_PATH=<godot> node scripts/runtime-coverage-smoke.mjs`，退出码 0，日志 `.noobi-private/representative-3d/coverage-smoke.log`。

路径修复后的真实游戏已能加载并跑通收集、兑换、激活、胜利和重开的声明式路线；当时报告仍有暂停恢复时间采样问题。首轮画面不通过：岛体方正、草地过亮、章鱼被平台遮挡，骑士比例和细节仍粗糙。Noobi 继续返修，不能把构建或流程通过写成美术验收通过。原始失败、后续截图和构建绑定报告保留在私有证据目录。

本次平台修复验证：`npm run verify` 通过（73 个文件、619 项测试）；`npm run smoke:ui` 退出码 0，已查看界面截图。该计数包含同时开发的方案编辑回归，不作为整款游戏通过证据。
