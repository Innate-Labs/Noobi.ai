# Noobi 平台专项：制作进度与步骤恢复

日期：2026-09-25。状态：开发者自验完成，待用户验收。

后续记录：用户回复“开始下一个阶段的内容”，同意进入故障分类、有界重试与累计执行预算专项。见 [后续报告](08-platform-failure-budget.md)。以下记录保留为本轮历史范围和验证结果。

## 目标与范围

用户在原方案继续入口交付后要求“开始下一个阶段”。本轮继续开发 Noobi 平台，目标是让制作进度可持久保存、失败可诊断、重启后能从已经完成的步骤继续。对应剩余清单 R01、R02、R07、R08 的部分内容，不等于原阶段 05 全部完成。

本轮没有推进《浮岛修复师》内容，没有为验证平台调用模型或生成素材。真实应用仍有制作任务运行，未重启或中断该任务；不能把现有运行实例当成本轮最终构建的完整验收证据。

## 已实现

- 项目与选定方案绑定的制作记录：工程检查/执行计划、核心玩法验证、画面样板验证、实现、独立评审、修复和交付。按适用条件标注“本次无需”。
- 每个关键步骤等待保存成功后再向下执行。临时文件加原子替换，串行写入；写盘失败回滚内存状态并停止后续制作，保留之前有效记录。
- 应用启动时将遗留的运行中记录标为中断，保存当时的任务状态与原因，等待用户明确继续。
- 每次继续形成独立执行记录；历史失败原因、已完成步骤及中断位置可查看，旧回调不能覆盖新一轮状态。
- 匹配原方案、工程源码指纹和制作配置时，复用已完成的 Planner/Implementer 回合。工程或策略不匹配则重新检查；复用期间检测到工程变化会停止并要求重新核对。
- 核心玩法、画面样板、独立评审和交付验证在恢复后重新执行。实现回合结束只表示该步骤结束，不能直接标记游戏交付完成。
- 会话顶部新增「制作进度」，显示当前步骤、已完成任务数、失败原因、恢复说明和之前的执行记录。过滤其他项目、其他方案和过期事件。
- 删除项目时清理对应制作记录；旧项目没有凭空补造历史，下一次开始或继续才建立记录。

## 开发与验收标准

| 要求 | 本轮证据 |
|---|---|
| 中断后已完成步骤不丢失 | 真实磁盘存储重新打开，将运行中任务转为中断，保留完成任务及历史 |
| 恢复不重复执行有效的完成回合 | 实际 Harness + 存储 + 工程指纹测试：同版本跳过 Planner/Implementer，新的评审和宿主检查仍执行 |
| 输入变化使检查点失效 | 修改真实临时工程文件后，重新执行规划及实现；制作规则变化不能复用旧输出 |
| 保存失败不能继续写游戏 | 持久化回调失败时阻止后续实现；模拟磁盘替换失败验证内存回滚、临时文件清理和恢复后的重试 |
| 不伪报交付 | 必要任务未完成时拒绝交付完成；UI 不将任务完成数描述为游戏品质百分比 |
| 界面与持久化记录一致 | 真实 Electron + 生产 Preload/IPC + Store，验证重新加载、历史、过期事件过滤及 390 像素窄窗口 |

模型回合输出使用测试替代，数据属于隔离临时项目。上述证据证明平台的调度、持久化和界面行为，不证明一次真实模型续作已产出合格游戏。完整阶段 05 的真实长任务、任意中断位置和版本回退验收仍待后续补齐。

## 用户验收

在当前工作树中运行下列命令可以重复无模型调用的隔离演示检查，不影响正在制作的用户项目：

```sh
export PATH="$PWD/.noobi-private/runtime/node_modules/.bin:$PATH"
node_modules/.bin/electron scripts/progress-ui-smoke.mjs
```

当前运行中的真实制作任务结束后，关闭旧应用，再从此工作树运行 `node_modules/.bin/electron .` 加载本轮构建。验收步骤如下：

1. 打开项目，在会话顶部展开「制作进度」。旧项目尚未有本轮记录时，应明确提示没有记录。
2. 在专门的测试项目选择方案并开始制作；应能看到当前步骤及实际完成数量。该步骤会调用真实模型。
3. 停止该测试项目并重启 Noobi；已经完成的步骤保留，当前步骤显示中断，不会自动开始制作。
4. 空输入点击「继续制作」；应增加执行次数，保留之前的失败或中断记录。工程及设置仍匹配且有完整检查点时显示“已复用”，随后重新评审及交付验证。
5. 修改测试工程源码后再继续；旧检查点不应复用。切换项目或方案时，不能显示其他项目的进度。

## 尚未覆盖与下一阶段

- 当前任务是宿主流水线步骤，不是每个角色、场景、素材、任务节点的动态依赖图。
- 仅在成功保存的完成回合之间恢复；回合中途写入一半的工程需要重新检查，没有任意工具执行位置续跑。
- 没有累计模型费用/总重试预算面板，也没有跨全部故障类别的无进展停止策略。
- 没有完整工程、素材引用、方案和构建的一键版本回退。
- 工程指纹覆盖现有源码扫描范围，跳过构建产物/缓存；外部依赖服务变化不等价于文件变化，因此评审与交付检查继续重跑。

建议下一阶段补齐故障分类、有限重试、重复失败检测及跨重启累计预算，使 Noobi 能解释卡在哪里、已尝试几次，以及何时需要用户处理。待本轮用户验收后进入。
