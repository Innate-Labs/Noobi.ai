# Noobi 自主图片建模实测

日期：2026-09-25。用户要求直接操作 Noobi，检查自主生成链路。测试对象为现有《浮岛修复师》的检查点升级。

## 操作与来源

从 Noobi 桌面项目制作输入框提交需求：生成独立参考图，再按图制作青铜水晶灯笼，替换全部检查点并验证。进入方案选择后，实际派发的是 option-2「共用灯笼结构，强调区域归属」。运行 ID：6005e46e-4d7f-4d0c-b3fc-17f3596c0177，开始时间 18:05:19（北京时间）。

参考图、规格、Three.js 源码、模型复核和游戏集成均由 Noobi 内部 Agent 完成。外部测试者只操作界面、读取证据和修改 Noobi 宿主提示，没有代写本次模型或生成参考图。修改前的游戏已备份在工作树 .noobi-private/noobi-autonomous-3d/backup-game/。

## 已观察到的成果

- Noobi 调用图片入口，按返回指引使用自身 ImageGen，生成并查看了单物体参考图。
- 自行编写三个区域变体的规格和 Three.js 工厂，导出后查看正、侧、背面，修正一次法线和青铜材质，再重新导出。
- 森林、工坊、灯塔模型分别为 2,584 / 2,960 / 2,944 个三角形；共 8,488 个三角形。没有调用外部 3D 模型 API。
- 替换三个检查点，保留原材质；晶体、纹饰使用独立发光材质和按时间插值的激活反馈，避免状态串联。
- Noobi 在实机截图中发现灯塔灯笼被风暴遮挡，将视觉位置外移，保留区域触发和恢复位置。

游戏内文件：model-sources/checkpoint-lantern-{forest,workshop,lighthouse}.{mjs,spec.json,review.md}；最终模型与多视图目录 ID 分别为 06269922-95de-47c9-ab21-cd9361897f99、352ee57e-6e45-4c5a-ae16-97dcbcd4f131、d91689dc-e981-4bd1-90cb-162ac39ee120。生产绑定见 scripts/asset_catalog.gd、scripts/main.gd 和 scripts/checkpoint_visual.gd。

| 素材工单的用途与替代关系不明确 | 最终门禁要求旧 model3d-checkpoint 和新 image-checkpoint-lantern-reference 直接接入生产代码，尽管旧模型已被替换、参考图用于建模 | Noobi 将旧工单改绑森林新模型，并把参考图加入菜单图鉴；后续应支持工单替代关系与建模参考用途，避免为了门禁添加展示内容 |
| 单图外观还原仍较简化 | 圆顶、底座、弯柱、晶体可辨认，但参考图的斑驳青铜、细小磨损和晶体通透感未还原；部分角度支柱遮挡晶体 | 如实记录为低多边形近似，不认定为高保真重建 |

| 完整游戏仍有明显美术与内容缺口 | 运行截图中角色、建筑、环境仍较粗糙；自动路线只覆盖现有切片 | 本轮不将完整 30–45 分钟游戏或整体美术标为已验收 |
