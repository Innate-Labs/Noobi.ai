# 图片参考 → Three.js 建模专项交付

日期：2026-09-25。状态：开发者自验完成，待用户验收。本报告不代表阶段 01、阶段 07 或完整游戏已经验收。

## 本次修改

Noobi 的默认 3D 制作流程改为：生成或导入参考图片 → AI 读取图片、记录部件与关键特征 → 编写可编辑的 Three.js 源码 → 宿主导出 GLB → 独立重新加载 GLB、生成正侧背三视图 → Reviewer 对照参考图判断是否需要修改 → 接入 Godot 游戏。

默认模式不需要 3D API，也不会按名称套用旧的固定模型模板。图片生成和 AI 编码仍使用相应服务与额度。设置 → 媒体 API 中新增“3D 模型制作方式”，默认选择图片参考建模；仍可明确切换至已配置的 3D API。免费音乐与音效库继续保留。

参考图必须先注册为工程素材；建模源码保存在 `model-sources/*.mjs`，旁边保存 `.spec.json`，记录参考图、部件、关键特征和推断的不可见表面。缺少输入时，工具返回补齐步骤，不会把占位模型报为完成。用户可以通过制作指令要求修改图片、部件、比例或材质，Agent 修改源码后重新生成。

宿主在隔离的 Electron 渲染器内执行建模代码，禁用 Node 和外部网络，设置 30 秒执行上限、100,000 三角形和 16 MiB GLB 上限。截图来自导出后独立加载的 GLB。参考图、规格、源码、模型和三视图的哈希记录在宿主私有目录，交付检查会发现文件缺失或变化。真实骨骼与动画片段是 `animation=true` 的必要条件。

外观检查由 Reviewer 对照图片进行，最多三轮局部修正；宿主的格式与几何校验不等同于外形相似度通过。素材记录保留 `visualReview: pending`，不会因文件有效而自动宣称视觉验收完成。

## 实际验证

- `npm run verify`：65 个测试文件、503 项测试通过，类型检查和完整构建通过。
- `npm run smoke:model3d`：使用真实 Electron 导出、重新加载 GLB 并截取三视图；纹理嵌入 GLB 成功；Node 访问和外部请求被拒绝；无限循环在时限内终止。
- Godot 4.7.1 导入并实例化样板成功，检查到 21 个网格、四个叶片和命名转轴层级。样板共 696 个三角形。
- 单元测试覆盖输入规格、路径边界、素材注册、几何预算、动画要求、文件变更、截图变更、修正版本和证据目录检查。
- 设置界面验证记录保存在 `.noobi-private/reference-ui/`；运行证据保存在 `.noobi-private/image-threejs-smoke/`。

可复现样板见 [examples/image-threejs](../../../examples/image-threejs/README.md)。其中参考图由本次 ImageGen 生成，源码根据图中结构编写。样板保留青色四叶、黄铜轮毂、琥珀中心、立柱和阶梯底座；背部结构根据单图推断。材质高光、石纹、磨损和精细比例仍属于近似，未作为高精度资产验收。

本机 img2threejs 技能的 `validate_sculpt_spec.py` 存在语法错误。此次采用其图片分析与分阶段修正原则，产品使用仓库内的宿主校验，未把本机技能作为运行依赖，也未宣称通过其全部雕刻验收步骤。

## 用户验收步骤

1. 打开设置 → 媒体 API，确认 3D 默认为“参考图片 → AI 编写 Three.js 模型”，音频仍为免费库。
2. 新建或继续制作 3D 游戏，要求先生成一个独立道具参考图，并按图建模；确认制作过程读取了图片，生成对应规格和源码。
3. 查看工程 `artifacts/model3d/` 下的参考图及正、侧、背截图，比较轮廓、部件数量、连接关系、配色与厚度；提出具体修改，再检查重建结果。
4. 在 Godot 游戏内检查实际模型的尺寸、碰撞、摆放和玩法用途。角色模型还需单独检查骨骼、动作和游戏驱动效果。

当前《浮岛修复师》的 16 个历史模型没有批量重做。本次完成的是默认生产链路及独立道具的真实运行验证，尚未验证新链路自动制作完整游戏或复杂动画角色的最终质量。后续重新制作资产时应用新流程，最终外观与游戏体验由用户验收。
