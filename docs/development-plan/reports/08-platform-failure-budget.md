# Noobi 平台专项：故障分类、有界重试与累计执行预算

日期：2026-09-25。状态：开发者自验完成，待用户验收。

## 目标与范围

用户在制作进度与步骤恢复交付后要求“开始下一个阶段的内容”。本轮实现故障解释、有限网络重连、跨重启重复失败检测及累计执行次数预算，对应 R04、R08 的部分范围。当前工作树为 `codex/stage-01-plan-selection`，基线提交 `58975ce5d0c8a7a12613d7ee3541bf595e0df274`。

修改仍在本地工作树，未提交或推送。保留此前的恢复功能及其他已有素材预览修改。只开发 Noobi 平台，没有推进用户游戏内容；测试没有调用真实模型或素材供应商。检查时真实应用仍有制作任务运行，没有重启或停止它。

## 本轮行为

1. 制作失败后显示故障类别、原始错误及建议。区分网络、账户配置、素材服务、编译构建、玩法画面检查、超时、预算、无进展、中断与未知故障。分类只用于诊断，不以文本分类结果自动授权重试。
2. 每个选定方案默认累计允许预留 40 个模型回合、6 个修复回合、6 次宿主网络重连。核心玩法、画面样板补齐与交付修复共享修复计数；同一模型请求因断线重新派发仍计入模型回合。
3. 派发前等待次数预留落盘；写盘失败则阻止模型请求。预留后失败、取消或派发结果不确定也不退回次数，因此这是保守的执行预算，不是实际计费次数。
4. 停止、重启、继续、换模型或制作规则都不清零同一选定方案的预算。历史执行记录保存截至当时的累计计数。旧版无计数记录明确标为“旧消耗未知”。
5. 单个回合的宿主网络重连还有 6 次上限，短暂收到模型响应只恢复连接状态和退避间隔，不清零总次数。永久账户错误、未知错误及中断未确认的写入者继续不自动重放。
6. 修复回合完成后保存输入源码指纹与规范化问题集合。同一阶段再次遇到相同工程和问题时，在启动下一次修复前停止。重启保留此判断；问题或源码变化可重新检查。中途取消/派发失败不冒充已完成的无效修复。
7. 「制作进度」新增累计预算。仅停止或失败时可明确增加 20 回合、3 修复、3 重连；宿主验证当前方案、忙碌状态和记录版本。连续点击不重复增加，保存增加记录，不自动开工、不抹掉失败与无进展记录。

## 用户验收步骤

等当前真实制作任务结束后，关闭旧应用，在此工作树运行：

```sh
export PATH="$PWD/.noobi-private/runtime/node_modules/.bin:$PATH"
node_modules/.bin/electron .
```

1. 打开用于验收的项目，展开「制作进度」中的「累计预算」。看到模型回合、修复和重连的已用/上限，明确显示费用未知。
2. 在有记录的测试项目停止并重启，确认计数保留；旧项目此前没有统计时显示旧消耗未知。
3. 在停止或失败状态点击「增加预算：20 回合 / 3 修复 / 3 重连」。看到上限增加、已用数不变、增加次数加一，项目仍不开始制作。
4. 展开历史，确认原失败原因和当时累计数保留。增加预算不会删除失败历史。
5. 有真实失败时核对故障类别和建议；网络、账户及构建问题应分别说明。旧错误文字仍作为历史原因保留，不等于增加预算后发生了新的失败。

无需消耗模型额度的隔离验证方式：在同一工作树运行 `node_modules/.bin/electron scripts/budget-ui-smoke.mjs`，读取输出及证据截图。该脚本使用独立临时数据，结束后清理临时目录。

## 边界与后续

- 预算只统计宿主调度的回合、修复和重连；一个回合内可能有多个模型内部重试、工具调用和素材请求。它不是金额、Token、供应商任务数或总耗时的硬上限。
- 无进展检测比较同阶段的最近一次完成修复输入，能识别源码及问题均未变化的重复。尚不识别“不断改无关文件”“多个版本来回震荡”或语义相同但完全改写的问题；累计次数上限仍生效。
- 本轮未实现完整工程版本回退、逐素材定点重试和供应商任务恢复，也未开放任意预算数值配置。
- 故障分类基于可信宿主上下文及错误信息，可能返回未知；保留原始原因供诊断，不强行归类为可修复。

## 远程压缩与认证请求故障（2026-09-26）

B 样板最终错误 `Error running remote compact task: error sending request for url (https://auth.openai.com/oauth/token)` 原先未被识别，继而按所在阶段落入 quality。这只是远程请求发送失败，不能据此断言登录过期，也不应建议修改游戏玩法。

新增独立执行故障诊断：请求发送/连接错误为 network；明确的认证拒绝、invalid_grant 或过期令牌为 account；远程限流为 provider；原因不足的远程执行失败保留 unknown。处理建议区分模型服务和素材服务，界面 provider 总称改为“外部服务”。原错误完整保留在现有长度限制内；已保存的历史记录不追溯改写。

核心玩法、视觉样板及通用交付修复入口都在预留新修复次数之前拦截这类执行故障。该诊断函数不参与自动重连授权，不新增重放规则、不退还已预留次数、不提高预算、不操作账户。预算耗尽和资源故障仍优先保留各自分类。
