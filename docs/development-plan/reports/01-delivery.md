## 实现与界面方向

沿用现有 React / Electron、字体和明暗主题，以并排的玩法路线卡片作比较；橙色描边和固定底部按钮明确表示当前选择。卡片正文可滚动，窄窗口改为单列，支持键盘单选和 Escape 返回。未使用外部组件参考图。

主要代码：

- `src/shared/planning.ts`：规划、版本、启动和分析尝试契约。
- `src/main/planStore.ts`、`planService.ts`、`planStarter.ts`：原子持久化、只读模型调用、结构校验、取消和启动幂等。
- `src/main/main.ts`、`preload.cts`：宿主 IPC 门控及现有 Harness 接入。
- `src/main/codexAppServer.ts`：规划取消传递到真实模型回合。
- `src/renderer/components/PlanDialog.tsx`、`App.tsx`、`HomeDashboard.tsx`：新流程与保存入口。

## 开发过程中发现并保留的记录

- 最初的独立测试脚本没有接入现有 Harness 必需的 ImageGen Skill，被既有门控拒绝；已修正测试配置。
- 一次额外尝试等待内部 Planner 完整结束，120 秒内没有完成并被停止。该时延保留为现有制作管线的已知观察；阶段 01 的交接证据采用服务端已接受的真实回合，不将中止记为完整制作成功。
- 首次桌面 IPC 测试使用了 URL 编码路径，宿主正确拒绝不存在的文件夹；修正测试工具后完成当前构建的真实启动验证。
- 早期测试页面因未清除前次订阅，收到重复回调；宿主事件日志只有一条启动记录。最终脚本直接核对宿主持久化事件并清理订阅。
- 阶段 00 已记录的依赖 audit 告警仍保留，未在本阶段扩大到依赖升级。
