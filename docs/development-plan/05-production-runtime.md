- 需求追踪：R08 R04，见 [REQUIREMENTS.md](REQUIREMENTS.md)。

- 代码入口（需开工时核实）：gameHarness.ts、production/、godotBuildStore.ts、productionCheckpointStore.ts、事件与项目状态。拟新增服务名称不构成既有实现。

## 本阶段开发标准

- 一次选定后内部测试和修复自动推进；超范围或超预算才需要产品用户重新决策。
- 先保持一个工程写入者；阶段 07 接入供应商原生任务恢复，不将 mock 视为真实恢复。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 05-A01 | 故障恢复 | 在写代码、构建、验证前后中断并恢复；不重复应用已完成变更，不伪报完成。 |
| 05-A02 | 版本绑定 | 报告/截图/产物必须匹配同一构建和方案；旧证据不能验收新代码。 |
| 05-A03 | 有界修复 | 同错误无进展时停止或升级处理；不能降低测试、删需求或绕过素材要求。 |
| 05-A04 | 可玩回退 | 坏改动失败后仍可运行上一版本；恢复后的方案与资产引用一致。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 05-U01 | 开始一个运行后停止并重启应用 | 看到真实已完成步骤和恢复入口。 |
| 05-U02 | 继续制作并查看运行记录 | 从合理检查点继续，累计消耗不归零。 |
| 05-U03 | 制造或使用失败版本后回到上一版本 | 上一版本可玩，失败原因和未完成内容可见。 |

## 范围边界与风险

- 本阶段不做：不做多写入者协作框架或无限制自主重试。
- 风险处理：进程中止时必须保留可诊断状态；支付额度和外部任务取消语义不能假定一致。

所有开发任务与适用验收项有证据，开发者自验通过后状态改为“待用户验收”，立即向用户汇报本阶段做了什么、怎么试、验证结果和遗留问题。只有用户明确验收通过，才改为“已验收”并进入下一阶段。存在未完成项时留在本阶段；范围变更必须先由用户明确接受。
