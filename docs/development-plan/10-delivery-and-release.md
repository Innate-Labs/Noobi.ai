# 阶段 10：一键游玩、导出与浏览器试玩

状态：开发中，整体未验收。实际进度以 [STATUS.md](STATUS.md) 为准。

## 目标与入口条件

在已声明支持的设备上，玩家无需开发配置即可运行作品。

- 前置条件：阶段 09 已由用户验收通过；对应记录可在 STATUS.md 查到。
- 需求追踪：R13，见 [REQUIREMENTS.md](REQUIREMENTS.md)。
- 开发前必读：[README.md](README.md)、[STANDARDS.md](STANDARDS.md)。
- 代码入口（需开工时核实）：Godot 导出服务、PreviewServer、项目启动入口、BuildManifest、发行脚本与用户说明。拟新增服务名称不构成既有实现。

## 开发任务

- [ ] 10-D01：桌面启动、加载、键位说明、音量/图形设置、暂停、存档位置与错误恢复。
- [ ] 10-D02：生成不含开发账户/供应商凭据的独立游戏包，明确目标平台、运行要求和版本。
- [ ] 10-D03：维护独立 Web 档位与试玩包，验证音频启动、全屏/鼠标锁定、加载与存档行为。
- [ ] 10-D04：冻结验收构建并导出同一产物；版本恢复、更新与存档兼容性清晰，公开发布为明确动作。

## 本阶段开发标准

- 先在 macOS 做真实干净环境验收；Windows 仅实测通过后标支持，缺设备则延期并显式说明。
- 验收方不需要生成模型账号、API Key 或 Godot 编辑器；本地导出不自动公开资料。
- 验收标准在开发前冻结；实现、测试与用户体验同步完成。不得靠降低标准使阶段通过。
- 每个任务有实际代码/产物及证据；外部能力和真实模型验证与 mock 测试分开记录。

## 自动验证与真实运行验收

| 编号 | 检查 | 通过标准 |
|---|---|---|
| 10-A01 | 干净环境 | 在独立用户或干净设备上解包启动，完成操作与保存/继续，不依赖开发工作区。 |
| 10-A02 | 打包完整 | 无缺资源、机器绝对路径依赖或凭据；导出 manifest 与候选构建一致。 |
| 10-A03 | 浏览器 | 在声明浏览器环境验证加载、音频、输入焦点、全屏和存档；明确隐私模式等限制。 |
| 10-A04 | 更新恢复 | 兼容更新可继续存档；不兼容有提示和保护，失败后可回到上一可玩版本。 |

代码变更完成后执行仓库要求的 `npm run verify`；涉及界面时执行 `npm run smoke:ui` 并实际检查截图。除此以外，执行上表要求的真实运行测试。命令、环境、退出码、日志位置、构建 ID 写入阶段报告；未运行必须写明，不预填通过。

## 用户验收步骤

验收前，开发者必须提供可运行版本、准确启动方式、示例输入/测试素材及下列操作所需的入口，不能只交代码 diff。

| 编号 | 你的操作 | 应看到的结果 |
|---|---|---|
| 10-U01 | 点击 Noobi 中的开始游戏 | 可直接进入成品，设置和存档可用。 |
| 10-U02 | 在另一验收环境启动导出包 | 无需开发配置或模型账号即可玩。 |
| 10-U03 | 打开浏览器试玩并操作、保存 | 支持范围内行为正确，不支持能力有清楚说明。 |

## 交付物

独立游戏包、Web 试玩包、构建清单、验收设备记录与操作说明。

- 使用 [REPORT-TEMPLATE.md](REPORT-TEMPLATE.md) 建立 `reports/10-delivery.md`。
- 提供本阶段提交、运行/构建版本、日志与截图或录像链接、已知问题。
- 用户反馈后，将实际结论写入报告并更新 STATUS.md。

## 范围边界与风险

- 本阶段不做：不默认搭建公网托管或商业分发平台；签名/公证凭据不可由开发授权推断。
- 风险处理：操作系统分发要求、设备与证书不足时精确说明可用交付形式，不声称全平台。

## 退出条件与汇报

所有开发任务与适用验收项有证据，开发者自验通过后状态改为“待用户验收”，立即向用户汇报本阶段做了什么、怎么试、验证结果和遗留问题。只有用户明确验收通过，才改为“已验收”并进入下一阶段。存在未完成项时留在本阶段；范围变更必须先由用户明确接受。

用户未回复、等待超时、测试全绿均不等于用户验收通过。禁止提前填写完成日期或用户意见。
