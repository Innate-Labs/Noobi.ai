# 功能规格：Windows 客户端

**功能分支**：`codex/windows-client`

**创建日期**：2026-08-12

**状态**：草案

**输入**：用户描述：“Noobi.ai 还需要有一个 Win 版本的客户端”

## 用户场景与测试（必填）

### 用户故事 1：在 Windows 上安装并启动 Noobi.ai（优先级：P1）

Windows 用户可以下载与其电脑匹配的 Noobi.ai 安装包，在不需要开发环境的情况下完成安装，
并从系统应用入口启动带有正确产品名称和图标的客户端。

**优先级原因**：如果用户无法可靠安装和启动应用，其他 Windows 功能均无法产生价值。

**独立测试**：在一台干净的 Windows 11 x64 设备上运行安装包，完成安装并从系统应用入口
启动 Noobi.ai，即可独立验证。

**验收场景**：

1. **假如**用户使用受支持的 Windows 11 x64 设备，**当**用户运行 Noobi.ai 安装包，
   **那么**用户可以完成安装，并在系统应用入口看到 Noobi.ai 的名称和产品图标。
2. **假如**Noobi.ai 已经安装，**当**用户从系统应用入口启动应用，**那么**主窗口能够正常
   打开，并且不会要求用户另外安装应用自身的运行环境。
3. **假如**安装或启动失败，**当**用户查看失败信息，**那么**用户能看到可执行的原因说明和
   恢复建议，而不是只有未处理的系统错误。

---

### 用户故事 2：完成核心游戏制作流程（优先级：P1）

Windows 用户可以配置模型服务、创建本地项目、启动和停止 Agent、查看实际工具调用、浏览
项目文件并打开受支持的游戏预览，获得与 macOS 版一致的核心制作体验。

**优先级原因**：Windows 版本必须能够实际制作项目，不能只是打开一个桌面界面。

**独立测试**：在 Windows 11 x64 上配置一个可用的模型服务，新建测试项目，让 Agent 创建
并验证一个最小 2D Web 游戏，然后停止并恢复一次 Agent，即可独立验证。

**验收场景**：

1. **假如**用户首次启动 Windows 版，**当**用户保存一个有效的模型服务配置并完成基础测速，
   **那么**配置可以安全保存，并在下一次启动后继续可用。
2. **假如**模型服务可用，**当**用户选择一个 Windows 本地目录并启动 Agent，**那么**项目
   文件写入该目录，制作阶段、工具调用、结果和错误会实时显示。
3. **假如**Agent 正在工作，**当**用户停止任务并随后恢复，**那么**已有项目文件不会丢失，
   可恢复的会话能够继续运行。
4. **假如**项目生成了受支持的预览产物，**当**用户打开预览，**那么**预览能够在客户端中显示；
   不支持内置预览的引擎项目会获得清晰的外部打开说明。

---

### 用户故事 3：管理 Windows 上的插件与本机依赖（优先级：P2）

Windows 用户可以查看、安装和配置 Skills 与 MCP，并能了解 Node.js、Godot、Blender、
Unity Hub 等本机依赖在 Windows 上是否可用。无法自动处理的依赖会给出明确说明，不会执行
仅适用于 macOS 的命令。

**优先级原因**：外部工具连接是 Noobi.ai 的重要扩展能力，但不应阻塞内置 2D Web 游戏流程。

**独立测试**：在未安装可选工具的 Windows 设备上打开插件和依赖管理，验证检测结果与操作
提示；随后安装一个本地 Skill 并配置一个测试 MCP，即可独立验证。

**验收场景**：

1. **假如**某项依赖未安装，**当**用户查看依赖管理，**那么**界面显示准确状态，并只提供当前
   Windows 环境支持的操作或官方安装指引。
2. **假如**用户安装或配置了 Skill/MCP，**当**用户启动下一轮 Agent，**那么**可用能力按既有
   信任和校验规则加载，失败的单项不会被误报为可用。
3. **假如**某个动作仅支持其他操作系统，**当**Windows 用户查看该动作，**那么**界面不会执行
   不兼容命令，并会说明替代步骤。

---

### 用户故事 4：安全升级、卸载和识别发行状态（优先级：P3）

Windows 用户和发布维护者能够识别安装包版本、架构、签名状态与校验信息；用户卸载客户端时，
自己选择的项目目录不会被删除。

**优先级原因**：这些能力影响公开分发的可信度和长期维护，但可以在核心可用版本之后完善。

**独立测试**：在 Windows 11 x64 上检查安装包属性，完成覆盖安装和卸载，然后确认用户项目
目录仍然存在，即可独立验证。

**验收场景**：

1. **假如**用户下载公开发行安装包，**当**用户查看文件和发布页，**那么**版本、目标架构、
   发布来源、签名状态和校验信息相互一致。
2. **假如**用户安装同一产品的更新版本，**当**安装完成，**那么**应用配置和用户项目仍可使用。
3. **假如**用户卸载 Noobi.ai，**当**卸载完成，**那么**应用程序被移除，但用户主动选择的项目
   目录和项目文件不会被删除。

### 边界情况

- 用户在 Windows on ARM、32 位 Windows 或其他未支持系统上运行安装包时，必须收到明确的
  架构或系统不受支持提示。
- 用户目录、项目路径或用户名包含中文、空格、括号和非 ASCII 字符时，安装、项目创建与
  Agent 工作不能因此失败。
- 系统策略禁止写入目标目录、启动子进程或访问系统安全存储时，应用必须停止相关操作并给出
  可执行的恢复建议。
- Windows Defender 或企业安全软件拦截未签名开发构建时，文档必须明确区分开发构建和公开
  签名发行版，不得建议用户长期关闭系统保护。
- 必需运行组件缺失、损坏或架构错误时，应用必须在启动或任务开始前报告缺失项，不能在 Agent
  工作中途以模糊错误退出。
- MCP Server 或外部工具使用 Windows 路径和参数时，空格、反斜杠和盘符不能被错误拆分或
  解释为 Shell 指令。
- 覆盖安装、卸载或应用崩溃都不得删除用户选择的项目目录。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须提供面向 Windows 11 x64 的可安装 Noobi.ai 客户端产物。
- **FR-002**：安装后的应用必须使用 Noobi.ai 产品名称、版本信息和产品图标，并提供标准的
  系统应用入口和卸载入口。
- **FR-003**：Windows 安装包必须包含启动 Noobi.ai 核心功能所需的应用运行组件，不得要求
  普通用户预先搭建源码开发环境。
- **FR-004**：Windows 客户端必须支持模型服务配置与基础测速、项目创建、Agent 启动/停止/
  恢复、实际工具调用查看、项目文件浏览和受支持的游戏预览。
- **FR-005**：Windows 客户端必须把应用私有状态保存到当前用户的标准应用数据位置，把用户
  项目保存到用户明确选择的目录。
- **FR-006**：API Key 和 MCP 秘密值必须通过 Windows 可用的操作系统安全存储保护，且不得
  出现在日志、事件历史、使用统计或错误详情中。
- **FR-007**：所有文件、进程和 MCP 操作必须正确处理 Windows 盘符、路径分隔符、空格、
  Unicode 字符和可执行文件扩展名，并继续执行目录越界与输入校验。
- **FR-008**：客户端必须为当前平台选择匹配的运行组件；架构不匹配、组件缺失或组件损坏时
  必须阻止相关功能启动并显示诊断信息。
- **FR-009**：插件中心必须在 Windows 上继续支持用户级与项目级 Skills，以及当前已经支持的
  MCP 连接类型，并保持来源、许可证、依赖和信任信息可见。
- **FR-010**：依赖管理必须准确检测 Windows 上支持的本机工具，只能执行经过白名单约束且
  适用于 Windows 的动作；不支持自动处理时必须提供官方安装指引。
- **FR-011**：安装、升级和卸载不得删除用户明确选择的项目目录。覆盖安装必须保留兼容的应用
  配置与凭据；不兼容的数据变更必须提供迁移或明确回退。
- **FR-012**：公开发行的 Windows 安装包必须提供可验证的发布者签名与校验信息。没有发布凭据
  的构建必须明确标记为开发构建，不得被描述为公开发行版。
- **FR-013**：发布流程必须能独立识别 Windows 构建的版本、架构和产物类型，并防止将 macOS
  产物或依赖错误装入 Windows 包。
- **FR-014**：Windows 构建必须通过安装、启动、核心流程、停止/恢复、插件配置、覆盖安装和
  卸载检查，验证结果必须能被发布维护者查看。
- **FR-015**：本功能不得把尚未实现的自动更新、Windows on ARM、32 位 Windows 或 Windows
  以外的新平台声明为已支持能力。

### 关键实体

- **Windows 发行产物**：供用户下载的客户端安装文件，包含产品版本、目标架构、产物类型、
  签名状态和校验信息。
- **平台运行组件清单**：描述目标平台与架构需要包含的运行文件，以及构建时实际包含、跳过或
  缺失的内容。
- **平台能力状态**：描述某项依赖或系统动作在当前 Windows 环境中的检测结果、可用操作、
  不可用原因和恢复指引。
- **应用私有数据**：保存在当前 Windows 用户范围内的设置、会话、事件和安全凭据引用；它与
  用户主动选择的游戏项目目录相互独立。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在干净的 Windows 11 x64 测试环境中，测试人员可在 5 分钟内完成安装并首次
  启动 Noobi.ai，且不需要安装源码开发工具。
- **SC-002**：Windows 发布验收中的核心流程场景全部通过：模型配置、基础测速、项目创建、
  Agent 启动/停止/恢复、工具调用展示、文件浏览和受支持的预览。
- **SC-003**：包含中文、空格和非 ASCII 字符的安装用户目录及项目目录，在规定的路径测试
  矩阵中全部通过。
- **SC-004**：对受支持设备，安装后首次主窗口在 15 秒内可见；启动失败时，100% 的已知必需
  组件故障都有明确诊断信息。
- **SC-005**：覆盖安装和卸载测试均不会修改或删除用户选择的项目目录；升级后兼容配置与凭据
  可继续使用。
- **SC-006**：公开发布页中的 Windows 产物全部能够对应到正确的产品版本、x64 架构、发布者
  签名和校验值；开发构建不会被标记为公开签名发行版。
- **SC-007**：Windows 运行日志、事件历史和使用统计的秘密扫描结果为零个未脱敏 API Key 或
  MCP 秘密值。

## 假设

- 第一阶段支持 Windows 11 x64；Windows on ARM、32 位 Windows 和 Windows 10 不在本功能
  的首发支持范围内。
- 首发提供标准安装版；免安装便携版和系统应用商店发行不在本功能范围内。
- Windows 版沿用当前 Noobi.ai 产品身份和本地优先数据模型，不新增云同步、多人协作或后台
  并行 Agent 队列。
- 自动更新仍是独立的后续功能；本功能只保证手动下载安装新版时的兼容覆盖安装。
- 公开签名需要可用的 Windows 代码签名凭据。没有凭据时可以生成和验证开发构建，但不能把它
  作为已经满足公开签名要求的发行版。
- Unity、Godot、Unreal Engine、Blender 的连接仍依赖各自的 Skill、MCP Server、编辑器插件和
  本机工具；Windows 客户端本身不等于这些外部工具已经就绪。
