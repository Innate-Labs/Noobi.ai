# Noobi v1 — 30-run acceptance register

10 candidate briefs × 3 independent runs. Current execution: **0/30**, not passed. At least 24 full autonomous successes and three distinct finished games are required. Existing engineering tests and development samples are not counted.

Before running, freeze actual component commit, model/effort, Godot version, device/resolution/graphics settings, input references with SHA-256, per-run analysis/production/media budget, and success criteria. Holdout cases must not be used to tune components before the freeze. Real video/image fixtures are required; missing assets remain unexecuted. Do not substitute synthetic video and claim real reference-play evidence.

Each host-owned run record must retain case and attempt IDs, chosen plan/version, reference hashes, start/end, all retries and costs (unknown is not zero), model/provider, source/build/artifact hashes, required reports, manual interventions, and actual result. A corrected run remains another attempt; no deletion of failures and no changing the denominator. Tests alone cannot label an edited game autonomous. Validate every report against the exported build.

Use `node scripts/benchmark-status.mjs benchmarks/noobi-v1` to see an honest register. This command reports bookkeeping, not an independent art/game-quality verdict. Production batch dispatch remains pending until the development samples meet the unchanged acceptance standard and the real fixtures and budget are frozen.

Exploratory playtest: 8–12 target users, voluntary feedback with chosen participant ID, actual game build, first-action time, blockers, completion, desire to continue and deviations from brief. No outreach is sent automatically. Human observation remains separate from machine reliability scores.
